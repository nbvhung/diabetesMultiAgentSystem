# ADR 0003 — Phase 03 serving and transaction boundary

Accepted 2026-11-02. Only Prediction and PostgreSQL integration; no graph/RAG/RL implementation.

PredictionResult v1.0 in contracts.py stays unchanged. New schemas/prediction.py inherits v1 fields with schema_version=1.1 and required preprocessing_version/inference_latency_ms, warnings and optional persisted_record_id. Runtime envelope changes explicitly to 2.1: integrated implementation enum, is_synthetic confirmation input, version/latency in trace and typed serving output union. Explicit 2.0 submissions are rejected; omit version to use current default or migrate clients to 2.1. Tests retain Phase 00 v1 contract and explicit scaffold coverage. Runtime v2.0 snapshots in DB are not automatically rewritten: no persistent snapshots existed before this phase. If importing external old snapshots, migrate/validate them separately. This is not a claim that strict v2.0 clients accept 2.1.

ASGI main:app and create_app() now default to integrated serving and PostgreSQL. create_app(prediction_enabled=False) is only an explicit legacy scaffold fixture/demo. No automatic fallback to scaffold or older model on serving failure. Registry metadata implementation=integrated means configured real implementation, not guaranteed dependency health; /models/current verifies artifact readiness. Missing/corrupt/mismatched artifacts produce UNAVAILABLE, no prediction. DB failures produce HTTP 503 with rollback and sanitized code.

ModelService is app-owned, lazy loaded once under RLock. Model and train-fitted preprocessing are checksum/version/schema verified; failed load is cached until app restart, not silently retried with another model. CPU default, MODEL_DEVICE=cuda explicit only if supported. torch eval/inference_mode, no fit or training; loaded pipeline and tensor model shared read-only under lock. Serving metadata derives bounds from original train indices, not held-out test, with manifest/split hashes. No signature or artifact authenticity claim: trusted deployment files required.

API owns one transaction and connection per run. PredictionAgent calls service then repository writes model registration, synthetic case, assessment and prediction linked to run_id before returning to Coordinator; these writes are pending until entire workflow snapshot/events save succeeds. Only after successful transaction commit does POST return 201. Any persistence exception swallowed into Coordinator FAILED is recognized at API boundary and raises 503, forcing rollback. Even final trace save failure rolls back all inserts. Unavailable model can still persist a degraded run with no prediction. Connection cannot be reused across requests. GET uses PostgreSQL snapshot and reconstructs typed response/trace, independent of process RAM.

Migration 0002 adds JSON result/response/event snapshots, preserving existing Phase 02 rows (nullable for older data). Existing rows without response return not found until explicitly migrated. Six table definitions remain based on explicit Alembic migrations, no ORM auto-DDL. Model version uniqueness/digest validation prevents reusing a version for different weights. Database timeouts configured on app-owned engine, no SQL parameters in exceptions/logging. No raw assessment log messages.

Coordinator changes are limited to persistence-mode limitations/warning and copying prediction version/latency/warnings to state/trace. Agent ordering, Safety and fallback are unchanged. Education remains abstention-only; real score is exposed under agent_results.prediction.output, no clinical labels. Full run remains DEGRADED because other tools are missing.

Tradeoffs: synchronous inference and psycopg work run in async route; throughput is limited and asyncio timeout is cooperative, not a hard cancellation bound on blocking work. Driver statement/connect timeouts bound DB work. This local-course MVP requires worker/async-job design before scaling. No auth, clinical calibration or deployment claims. Synthetic confirmation is a user assertion, not a detector of real patient data.
