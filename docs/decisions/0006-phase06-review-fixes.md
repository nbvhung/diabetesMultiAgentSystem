# ADR 0006 — close Phase 06 technical review

Accepted 2026-11-02, remediation only; no Phase 07 scope.

H1: frozen RLDecision v1 remains unchanged, but the current Coordinator validates completed RL outputs against the six canonical educational actions before recording or forwarding them. An unknown/empty action becomes FAILED/RL_ACTION_NOT_ALLOWED with no output. Education is skipped; output Safety sees a sanitized invalid-action marker and W04_ACTION_NOT_ALLOWED blocks the run. Safety policy is now safety-1.1 with an independent exact-membership rule in addition to clinical substring rules. WorkflowResponse also rejects a completed unknown RL action in a current snapshot; WITHHELD_BY_SAFETY is admitted only on blocked/failed runs. No raw rejected recommendation is returned in trace/result. This closes both the actual boundary and independent Safety-rule gap without silently changing v1's schema.

H2: rl/selection.py is the single masked selection + unseen-state baseline fallback implementation used by PolicyService.choose and in-memory validation/evaluation. Serving evaluation now requires visit counts or the actual service callback; raw-Q unmasked evaluation is diagnostic only. Validation policy selection now evaluates this exact behavior too. New policy education-q-1.1, manifest format 1.1 and evaluation_policy=serving-policy-fallback-v1 distinguish the corrected evaluation/export from previous artifacts. Reward/MDP/training algorithm/baseline unchanged. Re-executed notebook and recalculated metrics, no manual metric or Q edits. Old education-q-1.0 artifact retained as historical evidence, not silently loaded by current default.

M1: EducationOutput subclass schema 1.1 adds proposed_action/effective_action/override_reason. A shared render_plan returns those along with exact text/citations; source-based actions lacking evidence explicitly become REQUEST_CLARIFICATION with NO_EVIDENCE_FOR_REQUESTED_ACTION. Both Education and RL completed trace events carry structured proposed/effective fields. Existing action field remains the recommendation for compatibility. Safety veto redacts both fields. Metadata accepts only canonical actions.

Runtime wire version 2.4 includes these fields and the stricter snapshot invariant; SafetyDecision schema still 1.1 but policy_version explicitly safety-1.1. Existing v1 contracts, model 1.1 and RLDecision 1.0 unchanged. Prior runtime snapshots follow existing 409 explicit-review/migration behavior, no fabricated historical updates. Existing JSON DB columns need no DDL.

L1: notebook print now uses selected[1], matching manifest/report even after plotting loops. L2: Home now says Phase 06 and accurately describes integrated research prediction/knowledge/simulated education RL and Safety. Full pytest, actual PostgreSQL/Neo4j API verification, independent original-review probes, notebook/evaluation and frontend build rerun. Clinical validation, browser E2E and production rollout are not implied by these fixes.
