# Rule catalog — safety-1.1 (current)

Implementation: backend/app/rules/engine.py. Immutable Rule objects contain ID, category, description, executable condition callable, priority, action, severity and version=safety-1.1. RuleEngine evaluates all conditions then selects the highest priority (descending); ties sort by rule_id. Returned rule_ids include all matches in this deterministic order. No probabilistic decisions or model calls. Timestamp is the only deliberately time-dependent field; tests compare all other fields.

Built-in control decisions:

- P00_ALLOW: no condition matched → ALLOW/info; fixed default, not evidence of clinical safety.
- SYS01_SAFETY_FAILURE: missing/timeout/exception/wrong schema/stage/policy evaluation error → BLOCK/critical, workflow FAILED; synthetic system decision generated by Coordinator, not an inferred medical finding.

Emergency R01 has highest priority. Missing data REQUEST_CLARIFICATION has higher priority than ordinary unsafe-request rules; both stop business dispatch. Rule predicates are in code and the fixture contexts exercise their actual execution. Lexical normalization lowercases, expands Vietnamese đ→d and strips combining accents. Rules support bounded English/Vietnamese patterns, not all languages or paraphrases. Drug/dose rules deliberately conservative; no dosing tables or numeric diagnosis thresholds.

Escalation is a generic stop/referral, not a diagnosis of DKA or clinical triage. CDC states trouble breathing may require emergency care in its diabetes emergency information: https://www.cdc.gov/diabetes/about/diabetic-ketoacidosis.html (accessed 2026-11-02). This implementation does not copy numeric thresholds, dosing or treatment steps; it says to seek local urgent medical assistance and stops automated advice. The rule patterns for broader serious descriptions are conservative project policy, not a validated clinical decision instrument.
